# 使用与维护

安装和启动见[快速开始](https://lendevs.github.io/LenBot/guide/quick-start)。运行期间在面板中保存设置。手动修改配置或执行维护命令之前，请先停止 LenBot。

维护命令都在实例根目录中执行，写成 `uv run --no-sync python -m ...`。下文简写为 `python -m ...`。

## 面板一览

| 页面 | 用途 |
|---|---|
| 总览 | 连接状态、今天的统计、需要处理的事、各群实时动态、运行健康 |
| 对话测试 | 用某个群的设置或某个角色试聊，不发送到 QQ |
| 群聊 | 每个群一个工作台：现场（消息和每轮回复的经过）、会话、记忆、任务、学习、设置（含本群权限） |
| 角色 | 设定、说话方式、资料、表情、工具与技能、用在哪些群、草稿试聊、原文件 |
| 插件、能力 | 插件的安装和配置，以及 MCP、技能、网页和独立任务 |
| 模型 | 服务商、各用途的模型、向量模型、用量与上限 |
| 系统 | 设置（连接、全局权限、群聊、面板账号、数据保留、提示词、版本与更新、高级）和日志（系统日志、运行健康） |

## 账号与场景

账号写成 `平台:账号`，场景写成 `平台:group:群号` 或 `平台:private:账号`。平台目前只有 `onebot`。例如 Bot 是 `onebot:90001`，主人是 `onebot:70001`，群是 `onebot:group:80001`。

在面板中填写以下账号时，都使用这种写法。

- 主人
- 管理员
- 白名单
- 关系说明
- 群里的其他 Bot

本地记忆按场景分目录存放，人物画像存放在 `people/<完整账号>/`。

## 角色

角色包是一个目录。只有 `persona.yaml` 是必需的，里面至少写 `name` 和 `brief`；其他文件按需添加。

| 文件 | 内容 |
|---|---|
| `persona.yaml` | 名字、身份、性格、别名、工具和技能许可（必需） |
| `voice.md` | 说话方式 |
| `boundaries.md` | 底线 |
| `examples.yaml` | 人工编写的情境和台词 |
| `knowledge/` | 按需检索的资料 |
| `stickers/` | 表情图片和 `index.yaml` |

写法见[角色包说明](../../developer/personas.md)，也可以参考[示例角色](../../examples/personas/companion/)。

- 在角色的试聊页签可以用尚未保存的草稿开始一次独立的试聊。试聊开始后，发送消息时才会调用模型。
- 导入 ZIP 时会新建一个角色目录。各群使用哪个角色，在角色详情的**用到群**、群聊工作台顶部的角色名或群设置中选择。
- 对角色的修改保存后立即生效，正在回复的群等这一轮结束后用上新内容。

## 总览和群聊的快捷操作

### 群聊开关

总览群聊列表和群聊工作台右上角的开关。关闭后，这个群的消息照常记录，但 Bot 不再回复，也不主动发言，被 @ 时同样不回复。插件在这个群也不响应指令，不发送推送。重新打开后，Bot 从新消息开始处理，不补回关闭期间的消息。开关状态保存在数据库中，重启后保持不变。

### 全部暂停

状态卡片上的按钮，一次关闭所有群的聊天开关，效果与逐个关闭相同：消息照常记录，不调用模型。适合模型额度用完时使用。任一群开着时显示「全部暂停」，全部关闭后显示「全部恢复」，恢复会打开所有群。正在进行的回复会先结束，再关闭开关。

### 发送方式

真实发送到 QQ 时，状态卡片上有「发到 QQ」和「模拟发送」两个选项。选择模拟发送后 Bot 照常回复，回复与普通发言、插件消息和固定提示一起记录为模拟发送，不发到 QQ；给消息贴表情也只记录，不上传文件。模拟发送的发言同样计入每小时发言上限。主脑看到的发送状态为 simulated。开关保存在 `state/send-hold.json`，重启后保持不变；文件无法读取时按打开处理。改回「发到 QQ」后，之后的回复重新发到 QQ，之前模拟的内容不会补发。

### 断开 QQ

状态卡片 **…** 菜单中的操作。立即关闭 OneBot 连接。Bot 停止收发消息，正在进行的回复和后台任务会中断，面板仍然可以使用。需要重新连接时，在右上角的账号菜单中重启。

运行期间意外断线时，不需要这样操作。正向连接会自动重连，反向连接会等待 OneBot 重新连接。

### 手动连接 QQ

只在启动时第一次连接失败后出现。修复 OneBot 的问题后，点击这个按钮再试一次。

## 保存与重启

插件参数和插件启用的群保存后，只重新加载这个插件，聊天不会中断。其他需要重启才能生效的设置保存后，顶栏会提示有待应用的修改。

点击重启后会弹出确认窗口，列出受影响的设置和正在进行的工作。确认后会发生以下变化。

- LenBot 不再接收新消息和新工作。正在进行的这一轮回复完成后才停止。
- 后台任务中断，会话和文件保留，之后可以续接。
- 试聊停止。
- 新进程启动后，需要重新登录面板。

重启由 `len-bot` 启动器完成。直接运行 `python -m len_bot.next.host` 也可以启动程序，但没有重启功能。Ctrl-C 或 `systemctl stop` 会停止整个程序。程序异常退出后，查看终端输出或 `journalctl` 找到原因，修复后重新启动。

在终端中按 Ctrl-Z 会挂起进程，实例锁仍然被占用。请用 `fg` 恢复进程后再按 Ctrl-C。

## 在群里管理设置

在角色的工具许可中开启 `host_manage` 和 `tool_search` 并重启后，主人和全局管理员可以在群里直接让 Bot 修改设置，例如「把本群改成只回应 @ 吧」或「改完以后重启一下」。群管理员和本群管理员没有这项权限。

权限按实际发出请求的那条消息判断。Bot 调用管理、安静、提醒或任务类工具时，必须指明发出请求的消息。宿主读取这条消息的发送者，不接受 Bot 自己填写的账号。

可以修改的设置如下。

- 各群的聊天开关。Bot 能看到群名，直接说群名即可。
- 聊天和学习
- 提醒和任务
- 角色绑定
- 网页和记忆参数
- 模型的生成参数和预算
- 数据保留
- 已安装插件的启用和停用，以及插件的普通参数和启用的群

密钥和身份授权不能在群里修改，连接方式和需要停机转换的设置也不能。默认只保存修改，只有明确要求时才会重启。

跨群切换聊天开关时，最多等待目标群的执行锁 1 秒。锁仍被占用时报告操作失败，等目标群的这一轮结束后再操作一次。在本群的对话中关闭本群时，仍然在当前这一轮结束后生效。

## 插件

在**插件 → 发现插件**中可以从插件目录挑选，也可以从 Git 仓库安装或导入 ZIP 文件。安装分为两步。

1. **准备**。下载或解包插件，读取清单，检查宿主版本和 Python 版本是否兼容，以及系统是否支持。
2. **应用**。填写必填参数后应用。依赖没有变化的插件会直接重新加载。依赖有变化，或者插件声明需要重启时，要等到下次重启，在停机阶段统一安装依赖后再切换。

其他规则如下。

- 通过 Git 安装时可以指定分支、标签或提交，更新时沿用原来的选择。通过 ZIP 安装的插件，更新时重新导入新版本的包。
- 更换安装来源（例如从 Git 换成 ZIP）时，需要明确选择替换。
- 插件和 LenBot 使用同一个 Python 环境。依赖冲突时会显示原始错误，按其中的版本约束调整插件依赖。
- 停用插件会保留参数和启用的群。卸载插件会删除源码和配置，保留插件数据。删除数据需要单独操作。
- 插件都存放在 LenBot 目录下的 `plugins/` 中，包括已安装的插件和候选版本，以及插件数据（`plugins/.data/`）。也可以直接把插件目录复制进去，这类插件不由安装器管理。
- 业务插件独立安装和更新，不随 LenBot 一起升级。群聊总结和 GSUID 桥接见[独立插件](../../developer/plugin-examples.md)。
- 旧实例需要从根配置和启用的群中删除 `clock` 和 `rss_broadcast` 的引用。`group_digest` 和 `gscore_adapter` 保留原有的参数和数据，更新宿主后安装同名的独立插件即可。

重建了 Python 环境后，请停止 LenBot 并执行一次下面的命令。

```sh
python -m len_bot.next.maintenance.plugin_dependencies
```

这条命令把所有已配置插件的依赖合并后安装一次。

## 本机代理的 fake-ip 模式

Clash 和 Surge 等代理软件开启 fake-ip（假 IP）或增强模式时，本机查询任何域名都会得到 `198.18.x.x` 这类保留地址，再由代理按域名转发。LenBot 在读取网页和获取图片时会拒绝保留地址，后台任务访问外网时也一样，因此这些请求全部失败。错误信息中会出现 `resolved to 198.18.… (私有或保留地址)`。

在根配置中填写代理实际使用的假 IP 网段，以及一个可以访问的 DNS JSON 服务。

```json
"network": {
  "fake_ip_networks": ["198.18.0.0/15"],
  "public_dns_url": "https://dns.google/resolve"
}
```

按域名连接时，如果解析结果落在假 IP 网段内，LenBot 会向 `public_dns_url` 查询真实的 A／AAAA 地址。确认是公网地址后，LenBot 固定连接这些地址。

- 接口必须接受 `name` 和 `type` 参数，并返回包含 `Status` 和 `Answer` 的响应。
- 查询失败，或者真实地址是私网地址时，这次请求报错。
- 直接写成保留 IP 的地址仍然会被拦截。
- 网段不能覆盖 `10.0.0.0/8` 和 `192.168.0.0/16` 这类真实的局域网，也不能是公网网段。
- 网段按代理软件自己的设置填写。

## 后台任务

### 资料

在**群聊 → 任务 → 任务空间与文件**中可以上传本群的共享资料。新建任务时，可以从共享资料中选择，也可以选择其他任务的文件和交付，最多 16 份。任务得到的是新建任务时的只读副本。

### 追问和续接

任务可以向请求人提问，等待回答期间不占用执行名额。任务结束后，可以明确要求续接，续接时使用原来的会话和文件。`worker.max_calls` 按每次执行计算，`max_tokens` 按整个任务累计的输入加输出 token 计算。

### 产物

文件生成以后，登记为交付和发送到 QQ 各是一个独立的步骤，每一步都有记录。在任务详情中可以预览和下载文件，也可以登记和发送。单个文件默认上限为 25 MiB。整个任务登记的交付累计默认上限为 500 MiB（`worker.max_delivery_bytes`），续接时累计值继续计算。

### 清理

在**群聊 → 任务 → 任务空间与文件**中可以对任务执行两种清理。

- 清理临时文件。只删除临时文件，会话、输入和产物都会保留。
- 释放环境。删除整个工作区，之后无法再续接。已登记的交付和共享资料会保留。

任务仍在运行，或者仍然占用着容器和浏览器会话时，无法清理。

### 渲染

任务镜像自带 `lenbot-render`，可以把 HTML 渲染成 PDF 和截图，也可以生成打印预览，例如 `lenbot-render out/document.html --pdf out/document.pdf --screenshot out/page.png`。

### 镜像

任务镜像从 `docker/next-worker/Dockerfile` 构建。源码更新后需要重新构建，并在停机后把 `worker.image` 改为新的标签。

## 记忆维护

普通删除会保留修改历史。遗忘会清除这个文件的正文和索引，以及旧版本和摘要。遗忘时还可以选择部分原话，不再从中重新学习。

手动修改了记忆文件，或者更换了向量地址、模型或维数后，停止 LenBot 并重建索引。向量配置在「模型 → 向量模型」中修改，修改后执行下面的重建命令；只改服务商名称时直接保存即可。

```sh
python -m len_bot.next.maintenance.memory_reindex
```

正文和修改历史会保留，目录摘要会被清除，之后按新的正文重新生成。

更换了表达学习使用的向量模型时，停止 LenBot 后执行 `python -m len_bot.next.maintenance.reindex_expressions`。

## 运行日志

宿主的所有组件都写入同一份日志，即实例目录下的 `logs/lenbot.jsonl`。日志目录可以在设置 → 上下文、媒体与日志中修改。日志每天轮转一次，默认保留 14 天。

每行是一条 JSON 记录，包含以下字段。

- `ts`（UTC 时间）和 `level`
- `source`，产生记录的模块
- `event`，事件名，例如 `receipt`、`turn_start`、`tool_call`、`model_call`、`message_sent`、`plugin_error`、`task_finished`
- `message`
- 关联 ID，存在时才写入，包括 `scene`、`platform_message_id`、`message_seq`、`turn_id`、`tool_call_id`、`tool`、`plugin`、`task_id`、`job`
- `error`，包括 `type`、`message` 和完整的 `traceback`

从收到消息到发出回复，中间开始的那一轮回复，以及模型调用、工具调用和插件处理，都可以按 `turn_id` 关联起来。任务按 `task_id` 关联。面板的**系统 → 日志**可以按级别、群、轮次、插件和任务筛选。在**群聊 → 现场**展开一轮回复，点「这一轮的运行日志」可以直接跳转到对应的记录。

日志会遮盖配置中的密钥和插件的密钥字段；下载日志文件和诊断包时，5 位以上的数字也会被遮盖。

回复诊断包包含消息、模型请求与回复正文，任务诊断包包含任务文字，分享前请检查内容。

终端只显示简短的一行，完整记录在日志文件里。维护命令（例如迁移和 `doctor`）开始和结束时，以及失败时，也会写入同一个文件。

## 检查实例

在实例目录中执行 `python -m len_bot.next.maintenance.doctor`。命令逐项输出以下组件的检查结果，格式为 JSON，每项一行。

- 配置
- 业务数据库
- 记忆处理库
- 本地记忆索引
- 插件，包括插件的数据版本和 KV 文件格式

数据库都以只读方式打开，Bot 运行期间也可以执行。任何一项失败时，退出码为 1。未配置的组件显示为 `disabled`。

## 升级与备份

面板启动 60 秒后检查一次新版本，之后每 24 小时检查一次，查询 GitHub Releases。检查失败时记录一条 WARNING `release_check`。根配置的 `panel.update_check` 设为 `false` 可以关闭后台检查。

源码安装升级时，先停止 Bot、试聊和其他写入数据的程序，更新代码与依赖，然后执行：

```sh
python -m len_bot.next.maintenance.upgrade run --snapshot ../lenbot-backup-20261023
```

这条命令持有实例锁，先把实例目录和配置引用的外部目录复制到快照，再恢复插件依赖并运行 doctor。任何一步失败都会从快照恢复。快照目录每次用新的，放在实例目录和外部数据目录之外。完成后启动 Bot。

要退回升级前的版本时，停机执行 `python -m len_bot.next.maintenance.upgrade restore --snapshot <快照目录>` 恢复数据，再换回旧版本的程序。

使用部署包或 Docker 更新器时，快照失败会重新启动旧版本，并在更新页显示快照错误。旧版本启动失败时，可在更新页执行「启动程序」。

配置或数据库的格式编号与程序不一致时，启动直接报错。

所有命令和程序运行共用实例锁 `.lenbot-instance.lock`。锁被其他命令占用时，命令会拒绝执行。请不要手动删除锁文件。

## 面板登录限制

面板登录按来源 IP 统计尝试次数。15 分钟内失败或正在校验的尝试达到 5 次后，这个 IP 的登录一律返回 429，不再校验密码。即使用户名和密码正确，也要等这个时间窗口过去。更换用户名不会重置次数。登录成功后，这个 IP 的计数清零。

面板部署在反向代理后面时，把代理的 IP 或网段填进根配置的 `panel.trusted_proxies`（默认 `["127.0.0.1"]`，例如 `["127.0.0.1", "192.0.2.8"]`），修改后重启。来自这些地址的请求按 `X-Forwarded-For` 和 `X-Forwarded-Proto` 确定客户端地址和协议，登录限制、写入请求的来源检查和 WebSocket 都用这个结果。代理需要保留 Host，并用自己的值覆盖传入的 `X-Forwarded-For` 和 `X-Forwarded-Proto`。

密码采用 PBKDF2-HMAC-SHA256、600000 次迭代，保存格式为 `pbkdf2_sha256$600000$盐$哈希`。

## 数据格式

LenBot 还没有发布。第一个 RC 之前，根配置、业务数据库、记忆处理库和本地记忆索引的格式编号都是 1，结构变化不带升级步骤。从第一个 RC 起，格式变化由 `upgrade` 的 `apply` 步骤升级。

## token 计量

任务的 `max_tokens` 按整个任务累计的服务商报告的输入加输出 token 计算。

- 被服务明确拒绝的 HTTP 4xx 请求（例如 401、429）没有 usage 时，修正问题后仍然可以续接任务。
- 已经被接受或中途中断的调用，以及 5xx 等错误，仍然记为用量未知。配置了任务 token 上限时，会暂停续接。
- 服务商未报告的用量记为未知。

`max_daily_tasks` 统计的是新建任务的数量，续接沿用原来的任务。普通成员可以为任务补充信息，确认类操作仍然需要任务管理权限。

每次模型调用结束时，宿主在业务库的 `usage` 表记一行：调用开始时间、场景、用途、模型连接、模型名，以及服务商报告的输入、输出和缓存命中 token。表达学习、记忆整理、后台任务、语音转写和向量调用都写进这张表。保留期清理请求正文和旧轮次时不动它。

每日 token 限额按 `usage` 里当天的输入加输出 token 计算，包括公共场景、已移除的场景和保留的试聊。ASR 和 embedding 在**模型 → 用量与上限**中单独列出，不计入每日限额。已经报告的 token，无论调用最终是否失败，都计入限额。

## 测试实例副本

停止 Bot 后，可以复制一份用于测试的实例。


配置校验失败时会直接报错。副本中的模型、插件和任务服务正常运行。

## 不连接 QQ 的开发输入

配置 `onebot: null` 和 `delivery: "simulated"` 时，LenBot 不连接 QQ。

- 同时配置 `panel: null` 时，`len-bot` 从标准输入逐行读取原始的 OneBot 事件 JSON。读到输入结尾后，处理完已收到的消息就退出。
- 配置了面板时，面板、插件和 MCP 正常运行，可以在面板中试聊，直到明确停止。

两种情况下，模型调用和插件自身的网络请求，以及后台任务，都会真实执行。

表达回放见[公开回放用例](../../examples/replay/)。
