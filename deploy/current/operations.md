# 使用与维护

安装和启动见[快速开始](https://lendevs.github.io/LenBot/guide/quick-start)。运行期间在面板中保存设置。手动修改配置或执行维护命令之前，请先停止 LenBot。

维护命令都在实例根目录中执行，写成 `uv run --no-sync python -m ...`。下文简写为 `python -m ...`。

## 面板一览

| 页面 | 用途 |
|---|---|
| 总览 | 连接状态、当日统计、待处理事项、各群实时动态、运行健康 |
| 对话测试 | 用某个群的设置或某个角色试聊，不发送到 QQ |
| 群聊 | 每个群一个工作台：现场（消息和每轮回复的经过）、会话、记忆、任务、学习、设置（含本群权限） |
| 角色 | 设定、说话方式、资料、表情、工具与技能、使用的群、草稿试聊、原文件 |
| 插件、能力 | 插件的安装和配置，以及 MCP、技能、网页和后台任务 |
| 模型 | 服务商、各用途的模型、向量模型、用量与上限 |
| 系统 | 设置（连接、全局权限、群聊、面板账号、数据保留、提示词、版本与更新、高级）和日志（系统日志、运行健康） |

## 账号与场景

账号写成 `平台:账号`，场景写成 `平台:group:群号` 或 `平台:private:账号`。平台目前只有 `onebot`。例如 Bot 是 `onebot:90001`，主人是 `onebot:70001`，群是 `onebot:group:80001`。

在面板中填写以下账号时，都使用这种写法。

- 主人
- 管理员
- 白名单
- 关系说明
- 群内其他 Bot 的账号

本地记忆按场景分目录存放，人物画像存放在 `people/<完整账号>/`。

## 角色

角色包是一个目录。只有 `persona.yaml` 是必需的，至少包含 `name` 和 `brief`，其他文件按需添加。

| 文件 | 内容 |
|---|---|
| `persona.yaml` | 名字、身份、性格、别名、工具和技能许可（必需） |
| `voice.md` | 说话方式 |
| `boundaries.md` | 底线 |
| `examples.yaml` | 人工编写的情境和台词 |
| `knowledge/` | 按需检索的资料 |
| `stickers/` | 表情图片和 `index.yaml` |

写法见[角色包说明](../../developer/personas.md)，也可以参考[示例角色](../../examples/personas/companion/)。

- 在角色的试聊页签可以用尚未保存的草稿开始一次独立的试聊。试聊开始后，发送消息时才会调用模型。
- 导入 ZIP 时新建角色目录。各群使用的角色在角色详情的**应用到群**、群聊工作台顶部的角色名或群设置中选择。
- 角色修改保存后立即生效，正在回复的群在本轮结束后应用。

## 总览和群聊的快捷操作

### 群聊开关

位于总览群聊列表和群聊工作台右上角。关闭后，该群消息照常记录，Bot 不回复、不主动发言，被 @ 时同样不回复；插件在该群不响应指令，不发送推送。重新打开后，Bot 从新消息开始处理，不补回关闭期间的消息。开关状态保存在数据库中，重启后保持不变。

### 全部暂停

状态卡片上的按钮，一次关闭所有群的聊天开关，效果与逐个关闭相同：消息照常记录，不调用模型。适合模型额度用完时使用。任一群开启时显示**全部暂停**，全部关闭后显示**全部恢复**，恢复会打开所有群。正在进行的回复会先结束，再关闭开关。

### 发送方式

真实发送到 QQ 时，状态卡片上有**发送到 QQ**和**模拟发送**两个选项。选择模拟发送后 Bot 照常回复，回复与普通发言、插件消息和固定提示一起记录为模拟发送，不发送到 QQ；给消息贴表情也只记录，不上传文件。模拟发送的发言同样计入每小时发言上限。主脑看到的发送状态为 simulated。开关保存在 `state/send-hold.json`，重启后保持不变；文件无法读取时按打开处理。切回**发送到 QQ**后，之后的回复重新发送到 QQ，之前模拟的内容不会补发。

### 断开 QQ

状态卡片 **…** 菜单中的操作，立即关闭 OneBot 连接。Bot 停止收发消息，进行中的回复和后台任务中断，面板仍可使用。需要重新连接时，在右上角的账号菜单中重启。

运行期间意外断线时无需此操作：正向连接自动重连，反向连接等待 OneBot 重新连接。

### 手动连接 QQ

仅在启动时首次连接失败后出现。处理 OneBot 的问题后点击该按钮重试。

## 保存与重启

插件参数和插件启用的群保存后，只重新加载该插件，聊天不中断。其他需要重启生效的设置保存后，顶栏提示有待应用的修改。

点击重启后弹出确认窗口，列出受影响的设置和进行中的工作。确认后：

- LenBot 停止接收新消息和新工作，当前回合完成后停止。
- 后台任务中断，会话和文件保留，之后可以续接。
- 试聊停止。
- 新进程启动后，需要重新登录面板。

重启由 `len-bot` 启动器完成。直接运行 `python -m len_bot.next.host` 也可以启动程序，但没有重启功能。Ctrl-C 或 `systemctl stop` 会停止整个程序。程序异常退出后，根据终端输出或 `journalctl` 处理原因，再重新启动。

在终端中按 Ctrl-Z 挂起的进程仍然占用实例锁，请用 `fg` 恢复进程后按 Ctrl-C。

## 在群内管理设置

在角色的工具许可中开启 `host_manage` 和 `tool_search` 并重启后，主人和全局管理员可以在群内直接让 Bot 修改设置，例如「把本群改成只回应 @ 吧」或「改完以后重启一下」。群管理员和本群管理员没有这项权限。

权限按请求消息判断。Bot 调用管理、安静、提醒或任务类工具时必须指明请求消息，宿主读取该消息的发送者，不接受 Bot 自行填写的账号。

可以修改的设置如下。

- 各群的聊天开关。Bot 可以看到群名，直接使用群名即可。
- 聊天和学习
- 提醒和任务
- 角色绑定
- 网页和记忆参数
- 模型的生成参数和预算
- 数据保留
- 已安装插件的启用和停用，以及插件的普通参数和启用的群

密钥、身份授权、连接方式和需要停机转换的设置不能在群内修改。默认只保存修改，明确要求时才重启。

跨群切换聊天开关时，最多等待目标群的执行锁 1 秒。锁仍被占用时报告操作失败，需在目标群本轮结束后重试。在本群对话中关闭本群时，在当前回合结束后生效。

## 插件

在**插件 → 发现插件**中可以从插件目录挑选，也可以从 Git 仓库安装或导入 ZIP 文件。安装分为两步。

1. **准备**。下载或解包插件，读取清单，检查宿主版本和 Python 版本是否兼容，以及系统是否支持。
2. **应用**。填写必填参数后应用。依赖没有变化的插件直接重新加载。依赖有变化或插件声明需要重启时，在下次重启的停机阶段统一安装依赖后切换。

其他规则如下。

- 通过 Git 安装时可以指定分支、标签或提交，更新时沿用原来的选择。通过 ZIP 安装的插件，更新时重新导入新版本的包。
- 更换安装来源（例如从 Git 换成 ZIP）时，需要明确选择替换。
- 插件和 LenBot 使用同一个 Python 环境。依赖冲突时显示原始错误，按其中的版本约束调整插件依赖。
- 停用插件会保留参数和启用的群。卸载插件会删除源码和配置，保留插件数据。删除数据需要单独操作。
- 插件存放在 LenBot 目录下的 `plugins/` 中，包括已安装的插件、候选版本和插件数据（`plugins/.data/`）。也可以直接复制插件目录到其中，这类插件不由安装器管理。
- 业务插件独立安装和更新，不随 LenBot 一起升级。群聊总结和 GSUID 桥接见[独立插件](../../developer/plugin-examples.md)。
- 旧实例需要从根配置和启用的群中删除 `clock` 和 `rss_broadcast` 的引用。`group_digest` 和 `gscore_adapter` 保留原有的参数和数据，更新宿主后安装同名的独立插件即可。

重建 Python 环境后，停止 LenBot 并执行一次以下命令。

```sh
python -m len_bot.next.maintenance.plugin_dependencies
```

这条命令把所有已配置插件的依赖合并后安装一次。

## 本机代理的 fake-ip 模式

Clash 和 Surge 等代理软件开启 fake-ip 或增强模式时，本机查询任何域名都得到 `198.18.x.x` 这类保留地址，再由代理按域名转发。LenBot 读取网页、获取图片和后台任务访问外网时都会拒绝保留地址，因此这些请求全部失败，错误信息中出现 `resolved to 198.18.… (私有或保留地址)`。

在根配置中填写代理实际使用的 fake-ip 网段，以及一个可访问的 DNS JSON 服务。

```json
"network": {
  "fake_ip_networks": ["198.18.0.0/15"],
  "public_dns_url": "https://dns.google/resolve"
}
```

按域名连接时，解析结果落在 fake-ip 网段内的，LenBot 向 `public_dns_url` 查询真实的 A／AAAA 地址，确认是公网地址后固定连接这些地址。

- 接口必须接受 `name` 和 `type` 参数，并返回包含 `Status` 和 `Answer` 的响应。
- 查询失败或真实地址是私网地址时，该请求报错。
- 直接使用保留 IP 的地址仍然会被拦截。
- 网段不能覆盖 `10.0.0.0/8` 和 `192.168.0.0/16` 这类真实的局域网，也不能是公网网段。
- 网段按代理软件自己的设置填写。

## 后台任务

### 资料

在**群聊 → 任务 → 任务空间与文件**中可以上传本群的共享资料。新建任务时，可以从共享资料或其他任务的文件和交付中选择，最多 16 份，任务获得新建时的只读副本。

### 追问和续接

任务可以向请求人提问，等待回答期间不占用执行名额。任务结束后可以明确要求续接，续接时使用原有的会话和文件。`worker.max_calls` 按每次执行计算，`max_tokens` 按整个任务累计的输入加输出 token 计算。

### 产物

文件生成后，登记为交付和发送到 QQ 是两个独立步骤，各自有记录。在任务详情中可以预览和下载文件，也可以登记和发送。单个文件默认上限为 25 MiB。整个任务登记的交付累计默认上限为 500 MiB（`worker.max_delivery_bytes`），续接时累计值继续计算。

### 清理

在**群聊 → 任务 → 任务空间与文件**中可以对任务执行两种清理。

- **清理临时文件**：只删除临时文件，保留会话、输入和产物。
- **释放环境**：删除整个工作区，之后无法续接，已登记的交付和共享资料保留。

任务仍在运行或仍占用容器和浏览器会话时无法清理。

### 渲染

任务镜像自带 `lenbot-render`，可以把 HTML 渲染成 PDF 和截图，也可以生成打印预览，例如 `lenbot-render out/document.html --pdf out/document.pdf --screenshot out/page.png`。

### 镜像

任务镜像从 `docker/next-worker/Dockerfile` 构建。源码更新后需要重新构建，并在停机后把 `worker.image` 改为新的标签。

## 记忆维护

普通删除保留修改历史。遗忘清除该文件的正文、索引、旧版本和摘要，并可以选择部分原话，之后不再从中学习。

手动修改记忆文件，或更换向量地址、模型或维数后，停止 LenBot 并重建索引。向量配置在**模型 → 向量模型**中修改，修改后执行以下重建命令；只修改服务商名称时直接保存即可。

```sh
python -m len_bot.next.maintenance.memory_reindex
```

正文和修改历史保留，目录摘要清除，之后按新正文重新生成。

更换表达学习使用的向量模型后，停止 LenBot 后执行 `python -m len_bot.next.maintenance.reindex_expressions`。

## 运行日志

宿主的所有组件都写入同一份日志，即实例目录下的 `logs/lenbot.jsonl`。日志目录可以在**系统 → 设置 → 高级 → 日志**中修改。日志每天轮转一次，默认保留 14 天。

每行是一条 JSON 记录，包含以下字段。

- `ts`（UTC 时间）和 `level`
- `source`，产生记录的模块
- `event`，事件名，例如 `receipt`、`turn_start`、`tool_call`、`model_call`、`message_sent`、`plugin_error`、`task_finished`
- `message`
- 关联 ID，存在时才写入，包括 `scene`、`platform_message_id`、`message_seq`、`turn_id`、`tool_call_id`、`tool`、`plugin`、`task_id`、`job`
- `error`，包括 `type`、`message` 和完整的 `traceback`

从收到消息到发出回复，期间的回合、模型调用、工具调用和插件处理都可以按 `turn_id` 关联。任务按 `task_id` 关联。面板的**系统 → 日志**可以按级别、群、轮次、插件和任务筛选。在**群聊 → 现场**展开回合后点击**本轮运行日志**，可以跳转到对应的记录。

日志遮盖配置中的密钥和插件的密钥字段；下载日志文件和诊断包时，5 位以上的数字也被遮盖。

回复诊断包包含消息、模型请求与回复正文，任务诊断包包含任务文字，分享前请检查内容。

终端只显示一行摘要，完整记录在日志文件中。维护命令（例如迁移和 `doctor`）的开始、结束和失败也写入同一文件。

## 检查实例

在实例目录中执行 `python -m len_bot.next.maintenance.doctor`。命令逐项输出以下组件的检查结果，格式为 JSON，每项一行。

- 配置
- 业务数据库
- 记忆处理库
- 本地记忆索引
- 插件，包括插件的数据版本和 KV 文件格式

数据库都以只读方式打开，Bot 运行期间也可以执行。任何一项失败时，退出码为 1。未配置的组件显示为 `disabled`。

## 升级与备份

面板启动 60 秒后检查一次新版本，之后每 24 小时检查一次，查询 GitHub Releases。检查失败时记录一条 WARNING `release_check`。根配置的 `panel.update_check` 设为 `false` 可以关闭后台检查。

源码安装升级时，先停止 Bot、试聊和其他写入数据的程序，更新代码与依赖，然后执行：

```sh
python -m len_bot.next.maintenance.upgrade run --snapshot ../lenbot-backup-20261023
```

这条命令持有实例锁，先把实例目录和配置引用的外部目录复制到快照，再恢复插件依赖并运行 doctor。任何一步失败都会从快照恢复。每次使用新的快照目录，放在实例目录和外部数据目录之外。完成后启动 Bot。

回退到升级前的版本时，停机执行 `python -m len_bot.next.maintenance.upgrade restore --snapshot <快照目录>` 恢复数据，再换回旧版本的程序。

使用部署包或 Docker 更新器时，快照失败会删除没写完的快照，重新启动旧版本，并在更新页显示快照错误。旧版本启动失败时，可在更新页执行**启动程序**。

部署包和 Docker 更新器的快照放在部署目录的 `backups/` 下，目录名以快照的 UTC 时间开头。面板**系统 → 版本与更新**列出每份快照的时间和占用，可以删除不再需要的快照。上次更新失败且尚未恢复时，恢复所需的快照不能删除；更新完成后删除该快照，更新页不再提供恢复。删除中途出错的快照标为不完整，可以再次删除。快照不会自动清理。

更新完成且仍可恢复时准备新版本，更新页会先确认。准备后更新页不再提供恢复，直到下一次更新完成；上一份快照留在 `backups/` 下。

配置或数据库的格式编号与程序不一致，或者业务数据库缺少当前格式的数据表时，启动直接报错，并提示用新的实例目录重新配置。

所有命令和程序运行共用实例锁 `.lenbot-instance.lock`。锁被其他命令占用时，命令拒绝执行。不要手动删除锁文件。

## 面板登录限制

面板登录按来源 IP 统计尝试次数。15 分钟内失败或正在校验的尝试达到 5 次后，该 IP 的登录一律返回 429，不再校验密码，用户名和密码正确也需等待时间窗口结束。更换用户名不重置次数。登录成功后，该 IP 的计数清零。

面板部署在反向代理后面时，把代理的 IP 或网段填进根配置的 `panel.trusted_proxies`（默认 `["127.0.0.1"]`，例如 `["127.0.0.1", "192.0.2.8"]`），修改后重启。来自这些地址的请求按 `X-Forwarded-For` 和 `X-Forwarded-Proto` 确定客户端地址和协议，登录限制、写入请求的来源检查和 WebSocket 都使用该结果。代理需要保留 Host，并用自己的值覆盖传入的 `X-Forwarded-For` 和 `X-Forwarded-Proto`。

Docker 部署中，宿主机经发布端口进入的连接都来自 Docker 网络的网关。配方只在宿主机的 127.0.0.1 上发布面板端口，因此 LenBot 在容器中把该网关与 `127.0.0.1` 同样视为可信代理，宿主机上的反向代理无需额外配置。

密码采用 PBKDF2-HMAC-SHA256、600000 次迭代，保存格式为 `pbkdf2_sha256$600000$盐$哈希`。

## 数据格式

LenBot 尚未发布。第一个 RC 之前，根配置、业务数据库、记忆处理库和本地记忆索引的格式编号都是 1，结构变更不提供升级步骤。更早版本写入的配置和数据不能直接使用，请使用新的实例目录重新配置，旧目录可保留作备份。从第一个 RC 起，格式变更由 `upgrade` 的 `apply` 步骤升级。

## token 计量

任务的 `max_tokens` 按整个任务累计的服务商报告的输入加输出 token 计算。

- 被服务明确拒绝的 HTTP 4xx 请求（例如 401、429）没有 usage 时，修正问题后仍然可以续接任务。
- 已被接受或中途中断的调用，以及 5xx 等错误，仍记为用量未知。配置了任务 token 上限时暂停续接。
- 服务商未报告的用量记为未知。

`max_daily_tasks` 统计新建任务的数量，续接沿用原任务。普通成员可以为任务补充信息，确认类操作仍然需要任务管理权限。

每次模型调用结束时，宿主在业务库的 `usage` 表记一行：调用开始时间、场景、用途、模型连接、模型名，以及服务商报告的输入、输出和缓存命中 token。表达学习、记忆整理、后台任务、语音转写和向量调用都写入该表，保留期清理请求正文和旧回合时不清理该表。

每日 token 限额按 `usage` 中当天的输入加输出 token 计算，包括公共场景、已移除的场景和保留的试聊。ASR 和 embedding 在**模型 → 用量与上限**中单独列出，不计入每日限额。已报告的 token 无论调用最终是否失败都计入限额。

## 测试实例副本

```sh

```

命令复制配置和配置中引用的实例文件，保留文件权限和符号链接。副本做以下调整：

- 不连接 OneBot
- 面板使用指定的端口

配置校验失败时直接报错。副本中的模型、插件和任务服务正常运行。

## 不连接 QQ 的开发输入

配置 `onebot: null` 和 `delivery: "simulated"` 时，LenBot 不连接 QQ。

- 同时配置 `panel: null` 时，`len-bot` 从标准输入逐行读取原始的 OneBot 事件 JSON。读到输入结尾后，处理完已收到的消息即退出。
- 配置了面板时，面板、插件和 MCP 正常运行，可以在面板中试聊，直到明确停止。

两种情况下，模型调用、插件自身的网络请求和后台任务都会真实执行。

表达回放见[公开回放用例](../../examples/replay/)。
