# 群聊表达

普通聊天由同一个 `mind` 模型读取完整的上下文，自行判断是否回复和回复谁，决定态度和要说的内容，以及使用哪些工具。`say.content` 就是要发送的正文，`react` 可以单独发送表情。引用、提及、选图和发送回执由宿主处理。

## 框架和角色的分工

框架提示词提供群聊 Agent 的基本能力：看清谁在对谁说话，判断要不要接、接谁，区分原话、猜测和查到的事实，用对工具。另外提供一套群聊里的一般说法，例如长短看需要、不复述对方、不说客套话，在角色材料没写到时使用。

口吻由角色包决定。标点、语气词、颜文字、口头禅、表情包用得多不多、怎样回答身份问题，都写在角色材料里，角色材料写到的以角色材料为准。框架提示词不规定标点、语气和字数，共用示范也不写台词。

框架里规定口吻，会让不同角色说出差不多的话，示范里的台词也会被模型照搬。

| 文件 | 负责的内容 |

| `next_direct.md` | `say` 正文参数的含义 |
| `next_react.md` | 表情工具的用法，只在开放 `react` 时加入 |
| `next_chat_examples.md` | 几个群聊情境里的判断和工具选择 |
| `next_recent_habits.md` | 最近几次发言里反复出现的词和表情图，附在本次参考材料末尾 |

提示词统一用中文，以第二人称称呼角色，不写死角色的性别。工具参数的含义写在工具定义里，提示词不再重复。

共用示范的情境避开回放用例中的原句。角色的台词和梗放在角色包的样例与设定中。

## 原则

以下原则来自实际群聊中的反面例子。

### 先想人物，再想台词

开口前先站在角色的位置想：此刻知道什么，把对方这句理解成什么，自己想要什么。想要的可以很小，例如想吃、想凑热闹、不想被拆穿。然后选角色会说的那句。最后检查一遍：换一个角色说这句话还一样吗？一样就是没写出性格。

### 前后衔接

回复要回应对方刚才那句话的意思，与自己之前说过的话保持一致，语气随话题变化。

普通话题可以只给一个具体反应或直接答案，不要求每次都写成笑话、点评或建议。不把对方的话复述一遍再点评，说完这件事就停，不替对方安排下一步。旧回想里的台词用于理解过去发生的事，不作为当前表达示范。

### 不刻意表现人设

角色的特点是背景，不需要每句话都拿出来证明。连续使用同一种嫌弃、撒娇或口头禅，就成了刻意表现人设。角色设定里的梗用在它原本的话题里。

### 被 @ 时不必逐条回复

几个人同时起哄时，可以用一句话一起回应，也可以只回应其中一个人，或者发一张表情。

### 关心具体的事情

关心不一定说出口，问一句细节、顺手帮忙也算。不干涉别人的作息。被对方说管得太多时，就不再提。

### 对方真的生气时先站在对方一边

等对方自己笑了，再一起笑。

### 表情包

表情包可以单独作为回复，也可以和一句话一起发：只发图用 `react`，一句话带图用 `say` 的 `sticker`。用得多不多由角色材料决定。认真的问题用文字回答。

`react` 的工具说明写明它单独发一张表情包图片、不带文字，免得模型把它当成发一个 emoji 的反应。

### 不照抄自己

模型会把历史里自己说过的话当成最直接的示范，几句口头禅一旦出现，就会越用越多，各群还会各自固定成不同的说法。每次请求时，宿主从原生历史里取最近 8 次 `say` 和 `react`。同一个词出现在其中六成以上的文字发言里并且不少于 4 条，或者同一张图用了 3 次以上，就在参考材料末尾写明次数，提醒下一条换个说法或换张图。群友最近 50 条消息里出现过的词算作话题，不计入。标点和文字配图的比例属于角色的口吻，不统计。这段提醒每次请求重新计算，不写入历史。

### 身份问题由角色决定

被问到是不是真人时如何回答，由角色材料决定，框架不强制声明。

`say` 的引用和 @ 默认不填写，只在不填写会让人误解对象时使用。

## 参考材料的来源

角色的身份、关系、边界和人工样例来自角色包。开启学习时，每轮开始会按近期的对话，选出最多五条已经采用的群聊说法，和风格一起作为宿主参考放进上下文。

原话、人工样例、学习参考和已发送记录在上下文中分别标明来源。

记忆抽取会把群友对相处方式的明确要求记为这位群友本人的偏好，不会把 Bot 某一次的语气整理成 Bot 的性格。

修改提示词或角色前后，可以用[表达回放](../examples/replay/)对比效果。
