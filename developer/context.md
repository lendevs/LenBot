# 上下文、压缩与模型输入

主脑沿用原有的 `mind_entries`、`mind_sessions` 和 `model_calls`。

## 主脑请求

请求按以下顺序组装。

1. 稳定的角色和能力 system
2. 已保存的回想和原生历史
3. 本次的参考材料

启用了本地目录摘要，并且当前群有有效的正文时，在组装请求时读取摘要并放入参考材料。记忆为空时，不注入概览说明。

一轮回复的开始时间是固定的。之后到达的消息批次和 wait 的结果，会提供新的真实时间依据。任务快照只列出活动身份、状态和待回答的问题，较长的结果通过实际的结束事件或 task 工具读取。

参考材料末尾可能附一段最近的说法，列出最近几次发言里反复出现的词和表情图，提醒下一条换个说法。这段内容每次请求从原生历史重新统计，不写入历史，规则见[群聊表达](expression-materials.md#不照抄自己)。

临时召回的内容不写入原生历史，也不作为旧段落摘要的来源。执行记忆工具前，先撤下旧的召回内容。群概览在下一次请求时重新读取，工具只完成一部分就报错时也是如此。配置或能力发生变化时，按最新能力重建请求前缀。

## 群聊与工具

### 消息批次

新到达的消息按批次组织，同一批次共用一个包含场景、日期和时区的头部。同一天内 UTC 偏移发生变化时，另起一个头部。每条消息保留以下信息。

- 原账号和平台 ID
- 精确到秒的时间
- 正文、回复和提及
- 媒体序号
- 撤回状态和发送状态

较长的批次只在完整的消息之间分组。单条消息过大时不截断，交给明确的预算错误处理。引用同一批次内的消息时不重复摘录，引用批次以外的消息时，摘录会标为节选。

### 工具定义

宿主自有工具的参数 schema 只移除 schema 节点上自动生成的 title，业务属性、默认值、约束和引用都保留。插件和 MCP 的工具定义原样使用。工具按名称装配，顺序保持稳定。

tool_search 返回工具名称和简短用途，并说明工具从下一次请求起生效。完整的 schema 只出现在请求的 tools 中。已发现的工具集合会一直保留，直到正常压缩时重置。工具停用后立即撤下。

### 任务和文件

提供给模型的 task 视图不再复用完整的面板 DTO。视图保留任务目标、实际状态和待回答的问题，以及结果和错误。文件保留原 ID 和是否存在，以及登记状态和上传回执状态。

send_file 返回可以操作的回执和原事件 ID，完整的平台原始帧留在已有的事件中。上传回执表示平台接口接受了文件，送达状态另行记录。

### 工具结果

原生的工具调用 ID 和参数保持不变，完整的结果组和不透明的续接字段也保持不变。近期的结果完整保留。较早的宿主自有 web_read 结果，在请求投影中保留文档 ID、来源、范围和重新读取的入口，原结果和旧段落摘要的来源仍然完整保存。外部工具的文本和错误原文不做裁剪。

## 预算与压缩

### 触发条件

压缩是否触发，只取决于有效输入的估算值与 `compaction.input_tokens` 的比较（计入 system、tools、原话和当前参考），输出不计入。硬性窗口检查另外使用输入加上当前输出额度计算。配置时要求输入阈值加上主模型的输出额度能放进窗口。缓存的内容仍然占用窗口，因此不扣除 cached_tokens。

### 估算方法

如果当前成功的请求与本次的绑定、投影策略、tools 和持久前缀都一致，就用实际的 prompt_tokens 加减变动的材料。其他情况下按 UTF-8 字节数启发式估算，并在调用记录中明确写下使用的方法。

新实例的默认值为输入 60000、近期 20000，回想输出跟随聊天模型的最长输出。首次配置向导按上下文长度填输入阈值：取 60000 和窗口扣掉最长输出后的四分之三中较小的一个。这些值都需要按实际使用的服务选择。

### 响应保存和续接

模型的响应完整存入原调用记录（包含 raw 响应），会话中保存真实的 assistant 和 tool 消息。

- 绑定设置为 `history_policy=native` 时，原样续接。
- 明确选择经过核对的 `omit-reasoning` 路由时，请求中省去可读的 `reasoning_content`，保留其他字段、签名和工具 ID。只有既没有内容、没有工具调用、也没有其他续接字段的纯思考 assistant 消息会被略去。这个路由自行维护签名续接，请求中带有一个稳定的 Session-Id，根据实例数据库、scene 和用途生成。

### 近期原文

`keep_recent_tokens` 是近期原文的目标量，实际保留的原文可以少于这个值。

已有 usage_assisted 输入时，用同一请求的实测输入与文本启发式估算之比，来校准近期原文和压缩后的空间估算。

一次准备过程同时返回消息和同一次的输入估算。本次摘要之后仍然使用已经得到的比例，发送端也使用同一份估算，以免下一个循环又回到按字节估算，再压缩一次。

### 切分与摘要

切分点不会拆开原生的工具组，但可以落在一次长交互中两个完整的工具组之间。摘要写成六节的回想，交接以下内容。

- 原请求
- 更正
- 已做和未做的事
- 原任务和资源的 ID

已经结束的闲聊合并为话题和结果，不逐条保留调侃、口头禅和寒暄。「我说过的话」只保留仍影响关系、承诺、更正或待办的内容；必要原话继续保留说话人、发送状态和适用情境。每次压缩也重新整理已有回想，避免旧台词不断累积成表达示范。修改摘要提示词后，下一次压缩开始使用新的整理规则。

一次摘要只读取旧的回想和即将移出的旧段落，不再附带完整的人格设定、tools 和保留的段落。手动压缩也计入当前参考的预算。

摘要成功、内容非空并且满足空间要求后，在原事务中移动起点，并重置已发现的工具集合。摘要失败时，旧的回想和原始记录保持原样。最新的不可拆分单位或摘要输入过大时，错误信息会给出估算值、预留量和窗口大小。

## 临时请求

普通聊天只有一份长会话，由主脑直接编写 say 的正文或选择 react。内部的 assistant 思考内容不会发到群里。

- vision 和 ASR 只处理本次的媒体。
- 插件的 generate 只使用插件明确提供的 system 和 prompt。
- 学习和记忆抽取沿用各自原有的游标和记录表，使用真实的样本，不复制主脑的历史。

这些请求使用各自所属绑定的输出额度。recap 单独使用 `compaction.max_output_tokens`。

`say.mention` 使用平台账号，例如 `onebot:70001`，格式与消息的发送者身份和平台发送端一致。只写账号本身、不带平台前缀时，工具参数解析阶段会直接报错。

自动压缩和手动压缩使用群选定的策略。插件压缩失败时记录原始错误并结束当前回合，已有回想、历史和压缩位置保留。

手动压缩从上下文准备阶段开始纳入当前轮次的记录。失败时保存原始错误，不推进压缩起点。模型的 HTTP 错误和协议错误通过现有的面板接口返回。

Pi 代理会校验请求中的 `max_completion_tokens`，要求它是正整数，并且不超过宿主的上限。合法的值原样用于预算、转发和记录。请求中没有这个值时，才使用宿主的值。未知字段仍然报错。`cacheRetention` 不作为通用协议字段发送。Pi 原有的重试和缓存保温都保持关闭。
