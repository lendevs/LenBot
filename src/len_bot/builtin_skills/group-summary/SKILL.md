# 群聊总结

用本任务的 `recall_chat` 读取当前群记录，围绕用户关心的话题输出报告。统计对象是实际读到的消息。任务没有开放 `recall_chat` 时，用 `ask_requester` 说明缺少原始记录。

## 资料范围

- 从任务目标和补充背景确定自然日或起止时刻、群时区和重点。「今天/昨天」按提出请求时的群本地日期；任务入口给出建立时间与场景时区，背景写明了别的日期就用那个日期。区间用两个带偏移的端点，`after`包含、`before`不包含。自然日按当地相邻午夜计算，夏令时那天可能不是24小时。
- `recall_chat(action="search", after="2026-09-28T00:00:00+08:00", before="2026-09-29T00:00:00+08:00")` 是形状示例，日期与时区换成本次范围。完整群日报省略query/who；指定话题检索时记下用的关键词，命中数量按检索结果报告。
- 首页顶层返回`snapshot`，后续页保持同一时间过滤和该snapshot，用顶层`next_offset`翻页，直到它为null。snapshot固定了本次查询可见的已落库记录。
- 每条`previews`通常只有160字符。它的`next_offset`不为null时，用`action="read", record=<原返回位置>, offset=<该条next_offset>`读到全文结束。顶层翻页offset和单条字符offset分开使用。需要判断引用或短句回应时，用`context`读附近原话。

## 分析与统计

把实际返回的资料和必要的阶段笔记留在`/workspace`，大范围分批读取和归纳，保留话题跨页的前后文。因时限或工具失败只读完部分范围时，报告写明已覆盖的时段、消息数和未完成的部分，然后结束这次执行。

- 统计用返回的真实`sender_qq`、`time`、`is_self`、`send_status`；同名的人按QQ区分，改过名字的同一QQ算一个参与者。`record`是读取位置，用来复查原话。失败、未确认和模拟发送的发言单独列出。
- 用程序计算消息数、实际发言人数、时间分布等所需数字，写清是否包含自身发言、媒体和检索筛选。只读了部分范围时，数字写成「已读取资料中的…」。
- 按实际讨论归纳主要话题、事件经过、明确的结论或分歧和约定的下一步。人名用原昵称，有歧义时附真实QQ；少量关键原话附原平台消息ID和时间。待办只写群里明确约定的事。
- 媒体内容按返回的识别文字描述；需要分析媒体但缺少工具时，在报告里列出未分析的部分。

## 交付

在`/workspace/out`写可读报告。用户需要图片时，用可用的绘图库和实际中文字体渲染摘要卡片，长内容分成多张或附上全文，字号保持可读。核对关键原话、数字和文件中的最终内容；能查看图片时检查文字是否被裁切，没检查的外观在说明里写明。

用`deliver_file(path, name, note)`登记完成的文件，在最终说明中给出实际范围、主要结果和未完成项。
