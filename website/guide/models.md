# 模型与用量

只配置一个聊天模型就可以使用全部聊天功能。本页说明如何添加服务商、为不同用途换用其他模型，以及向量检索、语音转写和用量上限。

## 服务商与协议

在**模型 → 服务商**中添加服务商，填写接口地址和 API Key，读取模型列表后可按名称或 ID 搜索，也可手动填写模型 ID。每个服务商可以设置 HTTP(S) 代理，留空时直接连接。

| 协议 | 用于 |
|---|---|
| `openai-chat` | OpenAI 兼容的聊天接口，例如 DeepSeek 和大部分国内服务商 |
| `openai-responses` | OpenAI Responses 接口 |
| `anthropic` | Anthropic Messages 接口 |
| `gemini` | Gemini 接口 |
| `openai-embeddings` | 向量 |
| `openai-audio` | 语音转写 |

搜索和读网页使用的第三方接口也作为服务商管理，见[联网与工具](./web)。

上下文窗口、输出上限和超时时间按服务商的文档填写。新建模型使用服务商默认温度。

测试模型时，**测试文本**调用一次模型，**测试工具调用**调用两次。读取模型列表后，用途中填写的模型不在列表中时，模型名下方会标出，常见原因是服务商下线了旧模型。

## 模型用途

在**模型 → 用途**中为各用途选择模型。每个用途直接显示服务商、模型名、上下文长度、最长输出和思考强度，OpenAI 兼容协议还有思考开关；超时、思考额度、失败重试等待等在**更多参数**中。未单独配置的用途使用聊天模型。

| 用途 | 配置名 | 作用 | 未单独配置时 |
|---|---|---|---|
| 聊天 | `mind` | 判断是否回复、决定回复内容和使用的工具，也负责整理记忆和学习 | 必需 |
| 看图 | `vision` | 为不支持图片输入的聊天模型提供图片描述 | 聊天模型开启**支持图片输入**时直接看图，并负责表情标注 |
| 记忆摘要 | `memory` | 编写记忆目录摘要 | 使用聊天模型 |
| 插件生成 | `learner` | 插件的单次文字生成 | 使用聊天模型 |
| 后台任务 | `worker` | 后台任务使用的模型 | 使用聊天模型 |
| 语音转写 | `asr` | 把语音消息转写成文字 | 不转写 |

聊天模型开启**支持图片输入**时，直接读取准备后的图片，每轮最多保留 4 张。下一轮需要再看同一张图时，会复用缓存的图片。已有的看图用途配置可以保留；聊天模型关闭图片输入后，改用该模型描述图片。表情标注使用相同的模型选择方式。

聊天模型有两档思考强度：普通回复使用 `reasoning_effort`，开启**首轮请求使用低档思考**后，收到新消息后的第一次请求使用 `quick_reasoning_effort`（`low`）。整理回合和整理回想同样使用 `quick_reasoning_effort`；该值留空时沿用主思考强度。

**失败重试等待**是重发同一请求前等待的秒数，向导和新建用途默认 `2, 5`：遇到 HTTP 429、5xx 或连接中断时，等 2 秒重发一次，再失败等 5 秒重发一次。请求超过超时时间不重试。留空表示不重试。重试过的请求在回合详情中标出次数。**测试文本**和**测试工具调用**不重试，失败时直接显示第一次的错误。

更换聊天模型后，已完成的工具调用记录转为历史资料；未完成的工具调用不能跨模型续接，必要时在群聊工作台的 **…** 菜单中开始新会话。

## 思考开关与回想长度

OpenAI 兼容协议的服务商用 `thinking.type` 开关思考时（例如 [MiMo](https://mimo.mi.com/docs/en-US/api/chat/openai-api)），在模型用途的**思考开关**中选择开或关；选择服务商默认时请求不带该字段。思考强度另外设置。

整理回想的输出额度默认等于聊天模型的最长输出，也可以在**系统 → 设置 → 高级 → 上下文压缩 → 回想最大长度**单独填写，清空后恢复默认。关闭思考（思考开关选关，或思考强度填 `none`）时，回想正文用全部额度；填写思考额度时扣除这部分；其他情况正文用一半额度，另一半留给思考。

## 模型调用失败

| 情况 | 报错给出的处理方向 |
|---|---|
| 输出额度用完 | 用途、本次额度、服务商报告的用量和要调大的设置 |
| 401、403 | 检查 API Key 和模型访问权限 |
| 429 | 稍后重试，或检查服务商额度 |
| 5xx | 服务商或中转服务出错，把 request id 交给渠道运营方 |
| 404，或服务商返回模型不存在 | 核对模型名，或读取模型列表后选择；同时核对接口地址 |
| 服务商返回超过上下文长度 | 用途中填写的上下文长度大于模型实际值，按服务商文档调小 |
| 无法连接地址、代理连接失败、响应超时 | 报错中写明地址和底层错误，检查地址、网络和代理，或调大超时 |

LenBot 发送前会按用途的上下文长度估算请求，估算超过时不调用模型，报错写明估算值和窗口，按提示调大上下文长度或调小最长输出。

总览把同一服务商、同一用途、同一类错误合并为一条，点开后显示最近一次失败调用的原始响应。总览的**运行健康**还按用途列出近 7 天最近一次成功和失败的时间，用于判断问题是否仍然存在。

## 向量检索

记忆默认使用全文检索。需要按语义检索时，准备一个 OpenAI 兼容的 embeddings 服务。使用 Ollama 时：

```sh
docker compose -f deploy/current/services.compose.yaml up -d embeddings
docker exec lenbot-embeddings ollama pull bge-m3:567m
```

然后添加 `openai-embeddings` 服务商，地址填 `http://127.0.0.1:11434/v1`。在**模型 → 向量模型**中开启记忆向量，选择该服务商，模型填 `bge-m3:567m`，维数填 1024。**测试向量接口**显示实际返回的维数。

开启学习的群可以在同一页单独配置学习向量。更换向量的地址、模型或维数后需要[重建索引](./memory#重建索引)。

## 语音转写

自动转写群内语音需要一个 OpenAI 兼容的转写服务：

1. 在**模型 → 用途**中打开**语音转写**，选择该服务。
2. 在**群聊 → 设置 → 参与方式**中打开**自动转写语音消息**。

在本地部署 whisper.cpp 的方法见仓库中的 [ASR 说明](https://github.com/lendevs/LenBot/blob/master/deploy/current/asr.md)。

## 用量与上限

**模型 → 用量与上限**显示今天和本月的 token 用量，按模型（本月再按日期）和按群与用途分别列出，也可以设置每天的 token 上限。总览显示的是同一组数字。

![模型 → 用量与上限：今天的 token 合计，按模型、按群和用途的调用次数与 token，以及各群的唤醒与发言](/screenshots/usage.png)

同一页的**唤醒与发言**按群、日期和唤醒方式列出唤醒次数、发言次数、发言率、主脑输入 token 和缓存命中 token。一个回合计一次唤醒；回合中发言、单独发送表情或给消息贴表情都计一次发言。

每次模型调用结束时，LenBot 把时间、群、用途、模型连接、模型名和服务商报告的输入、输出、缓存命中 token 记一行。统计和每日上限都按这些记录计算，清理旧的请求正文不影响它们。语音转写和向量调用单独列出，不计入每日上限。
