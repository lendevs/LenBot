# 模型与用量

只配置一个聊天模型就可以使用全部聊天功能。本页说明如何添加服务商、为不同用途换用其他模型，以及向量检索、语音转写和用量上限。

## 服务商与协议

在**模型 → 服务商**中添加服务商，填写接口地址和 API Key，读取模型列表后可按名称或 ID 搜索，也可手动填写模型 ID。每个服务商可以设置 HTTP(S) 代理，留空时直接连接。

| 协议 | 用于 |
|---|---|
| `openai-chat` | OpenAI 兼容的聊天接口，例如 DeepSeek 和大部分国内服务商 |
| `openai-responses` | OpenAI Responses 接口 |
| `anthropic` | Anthropic Messages 接口 |
| `gemini` | Gemini 接口 |
| `openai-embeddings` | 向量 |
| `openai-audio` | 语音转写 |

搜索和读网页使用的付费接口也作为服务商管理，见[联网与工具](./web)。

上下文窗口、输出上限和超时时间按服务商的文档填写。新建模型使用服务商默认温度。

测试模型时，「只测文本」调用一次模型，「测工具调用」调用两次。

## 模型用途

在**模型 → 用途**中为各用途选择模型。未单独配置的用途使用聊天模型。

| 用途 | 配置名 | 作用 | 未单独配置时 |
|---|---|---|---|
| 聊天 | `mind` | 判断是否回复、决定回复内容和使用的工具，也负责整理记忆和学习 | 必需 |
| 看图 | `vision` | 把图片写成文字描述交给聊天模型 | 聊天模型直接看原图；聊天模型的**能看图**关闭时不能看图 |
| 记忆摘要 | `memory` | 编写记忆目录摘要 | 使用聊天模型 |
| 插件生成 | `learner` | 插件的单次文字生成 | 使用聊天模型 |
| 后台任务 | `worker` | 后台任务使用的模型 | 使用聊天模型 |
| 语音转写 | `asr` | 把语音消息转写成文字 | 不转写 |

聊天模型有两档思考强度：普通回复使用 `reasoning_effort`，开启接话时少思考后，收到新消息后的第一次请求使用 `quick_reasoning_effort`（`low`）。整理回合和整理回想同样使用 `quick_reasoning_effort`；该值留空时沿用主思考强度。

更换聊天模型后，已完成的工具调用记录转为历史资料；未完成的工具调用不能跨模型续接，必要时在群聊工作台的 **…** 菜单中开始新会话。

## 思考开关与回想长度

OpenAI 兼容协议的服务商用 `thinking.type` 开关思考时（例如 [MiMo](https://mimo.mi.com/docs/en-US/api/chat/openai-api)），在模型用途的**更多参数 → 思考开关**里选开或关；选服务商默认时请求里不带这个字段。思考强度另外设置。

整理回想的输出额度默认等于聊天模型的最长输出，也可以在**系统 → 设置 → 高级 → 上下文压缩 → 回想最大长度**单独填写，清空后恢复默认。关闭思考（思考开关选关，或思考强度填 `none`）时，回想正文用全部额度；填了思考额度时扣掉这部分；其他情况正文用一半额度，另一半留给思考。

## 模型调用失败

| 情况 | 报错给出的处理方向 |
|---|---|
| 输出额度用完 | 用途、本次额度、服务商报告的用量和要调大的设置 |
| 401、403 | 检查 API Key 和模型访问权限 |
| 429 | 稍后重试，或检查服务商额度 |
| 5xx | 服务商或中转服务出错，把 request id 交给渠道运营方 |

总览把同一服务商、同一用途、同一类错误合并成一条，点进去能看到最近一次失败调用的原始响应。

## 向量检索

记忆默认使用全文检索。需要按语义检索时，准备一个 OpenAI 兼容的 embeddings 服务。使用 Ollama 时：

```sh
docker compose -f deploy/current/services.compose.yaml up -d embeddings
docker exec lenbot-embeddings ollama pull bge-m3:567m
```

然后添加 `openai-embeddings` 服务商，地址填 `http://127.0.0.1:11434/v1`。在**模型 → 向量模型**中开启记忆向量，选择该服务商，模型填 `bge-m3:567m`，维数填 1024。「测试向量接口」会显示实际返回的维数。

开启学习的群可以在同一页单独配置学习向量。更换向量的地址、模型或维数后需要[重建索引](./memory#重建索引)。

## 语音转写

自动转写群里的语音需要一个 OpenAI 兼容的转写服务：

1. 在**模型 → 用途**中打开**语音转写**，选择该服务。
2. 在**群聊 → 设置 → 参与方式**中打开**自动转写语音消息**。

在本地部署 whisper.cpp 的方法见仓库中的 [ASR 说明](https://github.com/lendevs/LenBot/blob/master/deploy/current/asr.md)。

## 用量与上限

**模型 → 用量与上限**显示今天和本月的 token 用量，按群和用途分别列出，也可以设置每天的 token 上限。总览显示的是同一组数字。数字来自模型服务的报告。

同一页的**叫醒与发言**按群、日期和唤醒方式列出唤醒次数、发言次数、发言率、主脑输入 token 和缓存命中 token。一个回合计一次唤醒；回合中发言、单独发送表情或给消息贴表情都计一次发言。

关于未报告用量的调用：

- 有些服务不报告 token 用量，这类调用单独计数。
- 设置了上限后，只要当天出现成功但未报告用量的调用，LenBot 无法确认是否超限，会暂停当天的模型调用，直到当地时间零点。
- 失败或中断且未报告用量的调用记为未知，这类调用不触发暂停。
- 语音转写和向量调用单独列出，不计入每日上限。
