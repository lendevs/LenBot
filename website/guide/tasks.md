# 后台任务

编写报告、整理资料或制作网页等工作需要几分钟到几十分钟，Bot 可以把这类工作交给后台任务。每个任务在单独的 Docker 容器中运行，由容器内的编程助手 Pi 执行。任务运行期间，群聊照常进行。

例如群友发送「帮我把这周群里聊到的游戏整理成一页表格」，Bot 可以将其交给一个任务，完成后把文件发回群内。

后台任务默认关闭，聊天和查询资料不依赖它。

## 启用

需要一台能运行 Docker 的机器，Windows 上可以使用 WSL2。

1. **构建任务镜像**。在仓库根目录执行 `docker build -t lenbot-worker:local -f docker/next-worker/Dockerfile .`。
2. **配置任务环境**。在**能力 → 后台任务**中打开开关。表单按本机填好以下内容，核对后选择任务模型是否支持推理并保存。
   - 任务镜像 `lenbot-worker:local`
   - Docker 程序路径和 Docker socket
   - 当前账号的 `uid/gid`
   - 实例目录下的工作目录 `task-workspaces`、运行目录 `task-runtime` 和交付目录 `deliveries`

   三个目录必须互相独立、Docker 可以访问，且容器的 `uid/gid` 有读写权限。
3. **选择模型**。任务默认使用聊天模型。需要单独的模型时，在**模型 → 用途**中打开**后台任务**并选择。
4. **按群启用**。在**群聊 → 设置 → 提醒与任务**中打开**允许委托任务**，在**群聊 → 设置 → 权限**中设定谁可以委托任务。
5. **角色许可**。角色的工具许可中需要有 `delegate`、`task` 和 `tool_search`。任务需要使用的技能也要包含在角色的技能许可中。

任务容器没有网络。模型请求和公网请求都由 LenBot 转发，密钥只保存在宿主。

## 使用

### 资料

在**群聊 → 任务 → 任务空间与文件**中可以上传本群的共享资料。新建任务时，可以从共享资料或其他任务的文件和交付中选择，最多 16 份，任务获得只读副本。

### 追问和续接

任务可以向发起人提问，等待回答期间不占用执行名额。任务结束后可以明确要求续接，续接时沿用原有的会话和文件。

### 产物

文件生成后，登记为交付和发送到 QQ 是两个独立步骤，各自有记录。在任务详情中可以预览和下载文件，也可以登记和发送。

### 清理

- **清理临时文件**只删除临时文件，保留会话、输入和产物。
- **释放环境**删除整个工作区，之后无法续接，已登记的交付和共享资料保留。

### 渲染

任务镜像自带 `lenbot-render`，可以把 HTML 渲染成 PDF 和截图。

## 发送到 QQ

OneBot 必须能读取交付目录。设置方法分两步。

1. 把交付目录以只读方式挂载给 OneBot。
2. 在**系统 → 设置 → 连接 → 更多设置**中，把**OneBot 可见的文件目录**（`onebot.upload_visible_root`）设为 OneBot 一侧看到的路径。

登记为交付和发送到 QQ 是两个步骤，发送结果见任务详情中的发送记录。

## 重启

重启会中断正在执行的任务。这些任务标记为中断，会话和文件保留，可以续接。排队中的任务继续排队。

任务镜像的源码更新后，需要重新构建镜像，并在停机后把 `worker.image` 改为新的标签。
